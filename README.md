# 本地 Agent 工作台（local_agent_v2）

面向**离线内网环境**的个人 AI 工作台：一个文件夹就是你日常工作的空间，
AI 助手在里面帮你处理办公文档、代码开发和日常资料整理。

## 快速开始

**Windows：双击 `启动.bat`。** 浏览器会自动打开工作台；**关掉所有网页标签后，服务会在 5 秒后自动退出，cmd 窗口一并关闭**——不用再回去按 Ctrl+C。

启动器支持的参数（也可以直接命令行用 `python start.py`）：

| 命令 | 作用 |
|---|---|
| `启动.bat` | 按 `config.json` 启动，自动开浏览器 |
| `启动.bat 8081` | 换端口启动 |
| `启动.bat lan` | 局域网模式，同事用本机 IP 访问 |
| `启动.bat keep` | 关掉网页后**不**退出（服务常驻） |
| `启动.bat 8081 lan` | 换端口 + 局域网 |

它比直接跑 `app.py` 多做了几件事：

- **没有 `config.json` 时自动生成**，并把示例里写死的 `D:\我的工作台` 换成盘符确实存在的路径
- **端口被占用会分辨是谁占的**：是本工作台就直接开浏览器（不会起第二个）；是别的程序就自动往后顺延一个空闲端口
- **关网页即退**：见下节
- **出错不闪退**：双击场景看不到命令历史，异常信息会留在窗口里等你按回车

### 关网页即退

默认开启。前端每个标签页打开时向服务端登记，关闭时用 `sendBeacon` 注销；服务端要等**登记表变空**之后才开始 5 秒倒计时，所以这些情况都不会误伤：

| 场景 | 结果 |
|---|---|
| 刷新页面 | 新页面立即重新登记，倒计时取消，服务不断 |
| 开两个标签，关掉一个 | 还剩一个登记，服务继续 |
| 切到别的窗口 / 最小化 | 页面没关，不影响 |
| 关掉最后一个标签 | 5 秒后服务退出，窗口关闭 |
| 浏览器崩溃（没发出注销） | 服务不会退出，手动关窗口即可 |

不用网页、纯用 API 或脚本调用时，从来没登记过页面，服务不会自己退出。

想关掉这个行为，两种方式任选：

```jsonc
// config.json
"server": { "auto_exit": false }
```

或者单次启动时加 `keep`：`启动.bat keep`。倒计时秒数也能调：`"auto_exit_grace_s": 5`。

命令行手动启动（等价，供调试用）：

```bash
# 1. 配置模型与工作台路径
cp config.example.json config.json
#    编辑 config.json：填内网模型的 base_url / 模型名 / 工作台目录

# 2. 启动
python app.py

# 3. 浏览器访问
#    http://127.0.0.1:8080
```

## API Key 加密（可选但推荐）

配置文件里的 api_key 可以直接写明文，也可以用加密密文（与老项目 ENC: 约定一致），
启动时自动解密，避免 key 明文躺在配置文件里：

```bash
# 1. 加密你的 key，得到 ENC: 开头的密文
python encrypt_key.py encrypt "sk-你的key"

# 2. 把密文填到 config.json 的 api_key 字段（带 ENC: 前缀）
#    "api_key": "ENC:djGM6qE7yI..."

# 3. 正常启动即可，日志会显示"🔓 API Key 已从配置文件解密"
python app.py
```

- 机器密钥默认存于 `~/.local_agent_v2.key`（首次使用时自动生成），也可用环境变量
  `AGENT_KEY` 覆盖（比如放 U 盘随身携带）
- **密钥文件务必备份**：丢失后已加密的 api_key 将无法解密，需重新加密
- 其它命令：`python encrypt_key.py decrypt "ENC:..."` 解密查看；
  `python encrypt_key.py genkey` 查看/生成密钥

## 个人工作台结构

```
D:\我的工作台\              ← 你自己日常用的文件夹
├── inputs\                 ← 输入素材（网页上传落这里，按日期分类）
├── outputs\                ← AI 产出物（按 日期\会话标题 自动分类）
│   └── 2026-08-12\
│       └── 周报整理\
├── notes\                  ← 长期知识库（AI 可新建/编辑）
└── .agent\                 ← AI 内部状态（会话/记忆/日志，隐藏）
    ├── sessions\<id>\      ← 每个会话一个目录：消息+产出物清单+工作日志
    └── memory.db           ← 持久记忆库
```

## 设计要点（与旧版的区别）

| 旧版问题 | 新版方案 |
|---|---|
| 工作区=应用代码目录，产出物混入项目源码 | **工作区与应用分离**：独立工作台目录，应用只读写其中固定子目录 |
| 产出物靠"正则+时间窗"扫描，把 ls 列表/历史文件全当产物 | **产物=工具登记**：写文件类工具直接登记进会话产出清单，面板读清单，无启发式 |
| AI 写 work_logs/x 原样落盘，产出物跑到工作日志目录 | **写入白名单**：只能写 outputs/（自动分类）和 notes/；系统/输入目录一律拒绝 |
| 会话、产物、工作日志三处分散 | **会话目录化**：.agent/sessions/<id>/ 下 messages.json + artifacts.json + work_log.md 三者绑定 |
| 记忆靠启发式 | **持久记忆**（SQLite）：关键事实/用户偏好/会话摘要，对话时按关键词召回注入 system |
| 模型挂了转圈、必须重启 | **明确错误**：非 SSE 降级、超时看门狗、错误帧直达前端 |
| 思考过程大量输出到聊天正文 | **思考折叠**：content 里的 `<think>`/`<|start_thinking|>` 块（含切片拆开、漏写 `</think>`、无标签思考）自动拆进折叠块，答案区只留最终输出 |

## 思考过程处理（Qwen3 等思考型模型）

内网 vLLM 部署的 Qwen3 常把思考直接混进 `content`（`<think>...</think>`、`<|start_thinking|>`，
甚至只有 `<think>` 没有闭合标签）。启动时自动识别并拆分：

- **思考进折叠块**（默认）：`<think>` 块、漏闭合块、无标签的"用户希望/让我先分析…"思考 →
  折叠的「🤔 思考过程」块，答案区只显示最终输出
- 标签被流式切片拆开、`</think>` 漏写（正文另起一段）都能正确切分，答案不会被吞进思考块
- 也可在设置页切换：**完全隐藏**（并请求服务端关闭思考，省 token）/ **保留原文**

## 项目指令（AGENTS.md）

工作台根目录的 `AGENTS.md` 会作为“项目指令”每轮注入（也可在设置页直接编辑）：

```markdown
# 我的工作习惯
- 周报固定用「本周完成 / 下周计划 / 风险」三段式
- 所有金额保留两位小数
- 生成 SQL 时必须同时给出回退语句
```

优先级：全局角色 → 工作台约定 → `AGENTS.md` → 记忆/RAG → 全局铁律。
不同项目/客户的规矩放 `AGENTS.md`，不要都塞进全局铁律。

## 变更审阅与撤销

- 每轮写入都会先在 `.agent/snapshots/<会话>/<轮次>/` 备份；回复里的“✏️ 本轮改动 N 个文件”可查看逐行 diff。
- 点“↩ 撤销本轮”即可把新增文件删除、覆盖文件还原（撤销后历史里会标记“已撤销”）。
- 撤销只覆盖经工作台写入的文件；用户自己或外部程序改的文件不在快照范围内。

## 安全边界（沙箱控制）

- **读**：工作台内任意文件 + 电脑其他目录（只读）；`.env`/`.key`/凭据等敏感文件一律拦截
- **写**：白名单（`outputs/`、`notes/`），写其它路径（`inputs/`、`.agent/`、绝对路径、越界）直接拒绝
- **执行**：危险命令（rm -rf / 格式化 / git push 等）需弹窗确认；设置页可关「允许 AI 执行命令/代码」，
  关闭后 `run_command`/`execute_python` 不再注册，AI 只能读写文件
- **只读模式**：勾选后工具列表只保留读类，写操作后端强制拒绝
- **符号链接**：工作台内指向别处的链接一律拒绝（读/写/删除/预览/索引都跳过），
  防止把 `notes/` 下的链接变成越界写盘或外部文件进入知识库
- **跨站写请求**：浏览器发起的写请求若带 `Origin`/`Referer`，必须与当前访问域名一致；
  首次用 `?t=令牌` 登录后立即 303 清理地址栏，令牌不会留在浏览历史里
- **局域网共享不是多用户隔离**：共享令牌访问者共用会话、工作区及服务器目录权限；服务端签名的浏览器 cookie 仅用于归属任务审批/停止/延长。命令、Python 与 MCP 子进程继承工作台进程的操作系统权限，不构成沙箱；不可信输入/访问者场景应关闭代码执行或使用 OS 级隔离。

## 启动环境检测

`python app.py` 启动时自动检测并打印：Python 版本、工作台目录（盘符不存在会明确提示并退出）、
可选办公库（python-docx/openpyxl/python-pptx/pypdf/Pillow）是否安装、前端资源完整性、
模型服务连通性。离线机排查问题先看这段输出。

## 界面

- 左侧会话列表（新建/删除）
- 聊天区：SSE 流式打字机、思考过程折叠展示（reasoning_content）、工具执行进度、停止按钮、只读模式；
  离线大模型预热慢时显示「已等待 Ns」，看门狗快到点可点「再等 5 分钟」接着跑
- 产出物面板：当前会话产物清单（点击新窗口预览），随会话自动切换
- 📎 网页上传、🧠 记忆库管理、⚙️ 设置（含「运行」页的模型超时 / 后台记忆提取开关）、🌓 深浅主题

## 批量作业（一个目录一次跑完）

适用：一批格式相同的文件做同一件事（合同抽条款、发票提金额、简历打标签）。

1. 顶栏「批量作业」；或在文件浏览里勾多个文件 → 底部「批量作业 (n)」（目录与勾选自动带过去）。
2. 「目录」点「选择目录」逐层进入（和左下角文件浏览同一套交互），选好自动加载该目录文件；也可直接输入相对路径。
3. 填「每项要做什么」（模板提示词，每个文件各跑一遍），勾选要处理的文件。
4. 可先勾「先跑前 3 项预览」瞄一眼效果，再「开始作业」。

作业在后台单 worker 串行跑：可暂停 / 继续 / 取消 / 重试失败项；结果写 `outputs/<日期>/<作业名>/`，
台账在 `.agent/jobs/<id>/`（`job.json` + `items.jsonl`），面板可导出 CSV。
批量作业是无人值守：写文件自动放行，命令只跑你记住过的前缀，`ask_user` 直接跳过。

## 外接 MCP（MCP servers）

设置 →「外接 MCP」，全部在界面里配，不用手改 JSON：

0. 也可以先点一键模板「文件系统 / 网页抓取 / SQLite」自动填好表单，再按需改路径。
   模板已把超时设成 90s（首次要下载包，30s 容易握手超时）；下载完成后可以改回 20–30。
1. 「＋ 添加 / 编辑 MCP 服务」填：服务名、启动命令、参数、环境变量、超时。
   例：名字 `filesystem`、命令 `npx`、参数 `-y @modelcontextprotocol/server-filesystem "D:\资料"`。
2. 「保存并连接」→ 绿色「已连接」表示握手成功，后面显示工具数；红色「连接失败」会带错误原因。
3. 它的工具会以 `mcp__<名字>__<工具>` 出现在 AI 的工具列表里，对话里直接说需求即可（如“用文件系统看看 D:\资料”）。
4. 每行的「编辑」改配置（改名会替换旧项），「删除」移除并停掉子进程。

和 `config.json` 的 `mcp.servers` 是同一份配置：`{name, command, args, env, enabled, timeout}`。
离线机需先装好 node / python 和对应包；MCP 工具默认逐条向你确认，只读模式下直接禁用。

## 长会话压缩上下文

顶栏用量条旁的「压缩」（≥ 4 条消息可用）：把更早的对话压成摘要，只把「摘要 + 最近 6 条」发给模型。

- 完整对话不会被删，仍可回看 / 搜索 / 导出；只影响“发给模型的历史”
- 压缩后按钮变「已压缩」，再点一次即撤销（恢复完整历史）
- 配了上下文窗口时仍会自动压缩；手动压缩是提前释放，避免 8k 模型撞窗

## 离线部署

- 纯 Python 标准库（Python 3.8+），无第三方依赖；办公文档（word/excel/ppt/pdf/图片）工具可选，
  装了 `python-docx` / `openpyxl` / `python-pptx` / `pypdf` / `Pillow` 即自动启用——
  **之前离线机为老 agent 装过的包会直接复用**（同一 Python 环境），启动检测会显示哪些已就绪
- 前端零外部资源（无 CDN/联网字体），默认本机单用户
- 迁移时先拷贝项目目录与工作台目录；再在新电脑核对模型地址、工作台路径和密钥（见下方清单）

### 离线新电脑迁移检查清单

1. **预装运行环境与可选依赖**：离线准备 Python 3.8+ 安装包；如需 Word/Excel/PPT/PDF/图片解析，提前在联网机器下载匹配当前 Python/Windows 架构的 wheel 包，拷贝后用 `python -m pip install --no-index --find-links <wheel目录> python-docx openpyxl python-pptx pypdf Pillow` 安装。基础工作台本身不需要 pip 依赖。
2. **复制数据**：拷贝本项目目录和旧电脑的整个工作台根目录（包括 `.agent/` 会话、记忆、批量台账）；新电脑不要直接沿用旧电脑的盘符，先创建目标目录再调整配置。
3. **重配模型服务**：在模型设置中填新电脑可访问的 OpenAI 兼容 URL，例如 `http://192.168.1.20:8000/v1`；如果模型与工作台运行在同一电脑可用 `http://127.0.0.1:8000/v1`。确认服务端已启动并加载模型，再点「测试连接」。完全断网时必须使用 LAN/loopback 地址；公网 URL 不会离线可用。
4. **密钥处理**：`ENC:` 密文绑定到 `.local_agent_v2.key`。要继续使用旧密文，安全地一并迁移旧密钥文件；也可在新电脑重新设置 API Key 并重新加密。使用 `AGENT_KEY` 时，两台机器必须提供完全相同的值。不要把密钥文件提交或发送到不可信设备。
5. **配置监听**：本机访问保持 `server.host: 127.0.0.1`；可信局域网访问才改为 `0.0.0.0`，首次启动会生成共享访问令牌。只把令牌交给可信设备，并在 Windows 防火墙中仅允许可信局域网/专用网络访问工作台端口。令牌是共享门禁，不是多用户账户/数据隔离。
6. **理解服务器权限**：访问者看到的是运行工作台那台电脑上的会话、工作区与本机目录。`wbclient` 签名 cookie 只用于防止普通未持有身份的浏览器代替任务发起者确认、停止或延长任务；它不是登录身份系统。拥有共享令牌的人都拥有同一工作台权限，不能视为彼此隔离。
7. **谨慎使用执行工具**：`execute_python` / shell / MCP 子进程使用工作台进程的操作系统权限，不是 OS 沙箱。把 LAN 分享给其他人或处理不可信提示词时，建议在「安全与数据」关闭代码执行；若必须执行不可信代码，应使用独立低权限账户或经验证的操作系统级沙箱。
8. **启动验收**：运行 `python app.py --no-browser`，检查启动检测中的 Python、工作台路径和模型连通性；从另一台可信设备访问 `http://<服务器局域网IP>:8080`，输入令牌并做一次普通对话、文件读取和危险操作拒绝验证。不要在未验证防火墙与令牌前把端口暴露到公网。
